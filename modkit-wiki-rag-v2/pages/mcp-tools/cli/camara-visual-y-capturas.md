**EN:** camera, visual and captures: FOV, sensitivity, free camera, first person, screenshots, Zoi debug info overlay.

| Comando | Sintaxis | Que hace | Descripcion MCP actual | Que devuelve | Tipo |
|---|---|---|---|---|---|
| **camera_get_view** | `camera.get_view()` | Devuelve el estado en vivo de la camara activa: posicion, rotacion y fov. **[EXPERIMENTAL]** | [EXPERIMENTAL] [CLI: camera.get_view] Returns the live state of the active game camera: world position, rotation, the forward/right/up unit vectors derived from that rotation, the field of view actually in effect this frame, aspect ratio, projection mode, viewport resolution, the current inZOI camera mode (ShoulderView, QuarterView, BuildView, PhotoMode, ...) and the actor the camera is following. This reads the camera cache the renderer used, so fov here is the value in effect right now, which can differ from the user preference reported by camera.get_settings. aspect_ratio is the effective one used to render (the viewport aspect unless the camera constrains it), not the camera's raw AspectRatio field, which normally sits at an unused 4:3 default. Coordinates are Unreal world space: left-handed, Z-up, centimetres, with forward = +X, right = +Y, up = +Z. The camera interpolates and does collision avoidance every frame, so treat the result as a snapshot; pause the simulation first if you need a stable reading. | sin documentación oficial — el volcado es única fuente; requiere verificación en vivo | consultivo |

| **screenshot_get_last** | `screenshot.get_last()` | Devuelve el estado de la ultima captura solicitada y su ruta. **[EXPERIMENTAL]** | [EXPERIMENTAL] [CLI: screenshot.get_last] Returns the status of the most recent screenshot.capture issued in this process: where it is being written, whether the engine has finished writing it, and how long it has taken. Poll this after screenshot.capture until saved == true, then read the file at 'path'. pending == true means the engine has not rendered the capture frame yet — that is normal for the first poll, and can persist for seconds during a map load or while the window is minimised. Cheap to call: the response is a fixed handful of fields, so polling costs almost nothing. | sin documentación oficial — el volcado es única fuente; requiere verificación en vivo | consultivo |
| **screenshot_capture** | `screenshot.capture(Filename, show_ui, unique_suffix)` | Pide una captura al motor y devuelve su ruta absoluta. **[EXPERIMENTAL]** | [EXPERIMENTAL] [CLI: screenshot.capture] Requests an engine screenshot and returns the exact absolute path, directory and filename the engine will write to. The path is authoritative, not a guess: the engine resolves the final filename at request time. OFFSCREEN-SAFE: this is a GPU read-back of the game's own render target, not a desktop grab, so it works while the game window is fully covered by other windows, unfocused, or moved off-screen — you do not need to bring the game to the foreground. SLOW AND DELAYED: nothing is on disk when this command returns. The file is only written when the engine renders and presents its next frame, so expect at least one frame of latency, and much longer (seconds) while a loading screen is up, while the window is minimised, or when the game thread is blocked by a map load. Poll screenshot.get_last until saved == true before reading the file. Only one request can be pending engine-wide; this fails if one is already in flight, or if Photo Mode currently owns the capture delegate (in that case the engine would write no file at all). Call system.get_paths for the directory these files land in. | sin documentación oficial — el volcado es única fuente; requiere verificación en vivo | activo |
