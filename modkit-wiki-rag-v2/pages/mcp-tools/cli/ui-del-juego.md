## UI del juego

**EN:** game UI: find UI widgets (ui_find, e.g. the household money balance in the HUD), overlays, toasts, dialogs.

| **ui_find** | `ui.find(Text, Role, Name, Window, Limit)` | Busca en el arbol UMG visible y devuelve widgets con sus refs. **[EXPERIMENTAL]** | [EXPERIMENTAL] [CLI: ui.find] Searches the visible UMG tree and returns matching widgets with their refs, so you can act on something without pulling down a whole tree first. text matches the displayed (localized) label as a case-insensitive substring; name matches the widget's FName the same way; role must match exactly. Filters combine with AND, and results are limited to interactive widgets and text so an unfiltered search does not dump the tree. Only interactive results carry a ref and a rect. Returns an empty array when there is no world. | sin documentación oficial — el volcado es única fuente; requiere verificación en vivo | consultivo |
| **ui_get_node** | `ui.get_node(ref, Depth, max_nodes, include_offscreen, show_decor)` | Expande un nodo del arbol UI identificado por su ref. **[EXPERIMENTAL]** | [EXPERIMENTAL] [CLI: ui.get_node] Expands one node of the UI tree, identified by the ref that ui.get_tree or ui.find gave you. Use this for the parts ui.get_tree folded away ({role:'more'}) or cut with the node budget, instead of re-fetching the whole screen with a bigger budget. Unlike ui.get_tree this defaults to showing non-interactive structure too, since the point is to look closer. Fails when the ref no longer resolves - a window may have closed, or a list entry may have been recycled by scrolling, in which case re-query ui.get_tree for a fresh ref. | sin documentación oficial — el volcado es única fuente; requiere verificación en vivo | activo |
| **ui_get_tree** | `ui.get_tree(Window, Mode, max_nodes, Depth, include_offscreen, show_decor, verify_hit)` | Devuelve el arbol de widgets UMG visible como JSON. **[EXPERIMENTAL]** | [EXPERIMENTAL] [CLI: ui.get_tree] Returns the visible UMG widget tree as JSON - a text substitute for looking at a screenshot. Prefer scoping it: 'ui.get_tree GameOption' returns only that window and is far smaller than the whole screen. 'top' selects the top-most window, which is what you usually want right after a popup appears. Without --window the entire screen is returned, grouped by UI layer. Layout-only containers (CanvasPanel, Overlay, SizeBox, boxes) are folded away and their children lifted, label text is absorbed into the button/tab that owns it, collapsed or unpainted or off-screen subtrees are dropped, and more than 12 identical siblings collapse into a {role:'more', count:N} entry. Only interactive nodes get a 'ref' and a 'rect' - everything else is there to be read, not clicked. Scroll containers report offset/max/pos, and list views additionally report the total item count plus the index range that currently has entry widgets (items outside that range are virtualized away and have no widget at all, so you must scroll to reach them). When the max_nodes budget is hit the response carries a 'truncated' field - it never drops nodes silently. Fails if --window matches no visible window. This command never creates a widget, so it is safe to poll; widgets opened this very frame appear one poll later. | sin documentación oficial — el volcado es única fuente; requiere verificación en vivo | consultivo |
| **ui_list_windows** | `ui.list_windows()` | Lista las ventanas UMG de nivel superior en pantalla. **[EXPERIMENTAL]** | [EXPERIMENTAL] [CLI: ui.list_windows] Lists the top-level UMG windows currently on screen, without any of their contents. This is the cheapest UI query and the intended first step: pick a window here, then call ui.get_tree --window=<name> to see inside it. Windows are ordered top-most first (by UI layer z-order). Each entry carries 'counts' (nodes / interactive / scrollables) so you can tell how big the window's tree is before asking for it, and 'occluded' which is true when a modal above it means clicks cannot reach it. Only windows under the UI manager's root widget are reported; Cohtml-based UI and world-space widget components are not UMG and never appear. Returns an empty list when there is no world. This command never creates a widget, so it is safe to poll. Widgets that were opened this very frame have not been painted yet and show up one poll later. | sin documentación oficial — el volcado es única fuente; requiere verificación en vivo | consultivo |
| **ui_scroll** | `ui.scroll(ref, To, Offset, Delta, Index, wheel)` | Hace scroll en una caja o lista identificada por ref. **[EXPERIMENTAL]** | [EXPERIMENTAL] [CLI: ui.scroll] Scrolls a scroll box or list view identified by a ref from ui.get_tree. By default it calls the scroll API directly, which lands on the target in one step and makes the result easy to verify; the response carries the resulting offset/max/pos/at_end so you do not have to re-query. Pass wheel=true with --delta to synthesize a real mouse wheel instead, which is what you want when the thing under test is wheel handling itself (nested scroll boxes, scroll propagation) - that path is animated, so the reported offset may still be settling. to=index only works on list views and is the reliable way to bring a virtualized item on screen: items outside the displayed range have no widget at all, so you must scroll them into view before ui.get_tree can see them or ui.click can touch them. For a scroll box the offset is in slate units; for a list view it is in items. Fails when there is no world or the ref is not scrollable. | sin documentación oficial — el volcado es única fuente; requiere verificación en vivo | activo |
| **ui_click** | `ui.click(ref, Button, Double, Force, hold_ticks, X, Y)` | Hace clic en un widget UMG identificado por ref. **[EXPERIMENTAL]** | [EXPERIMENTAL] [CLI: ui.click] Clicks a UMG widget identified by a ref from ui.get_tree / ui.find. By default this synthesizes real mouse input at the widget's centre - it moves the cursor there, presses, and sends the RELEASE ON A LATER TICK, because the engine does not treat a press and release delivered in the same tick as a click. That means the click has NOT completed when this command returns: re-query ui.get_tree / ui.list_windows to see the result. Use hold_ticks if one tick is not enough. Because it goes through the real input path, hit testing, modality and input blocking all apply exactly as they do for a player - if something covers the widget the call FAILS instead of clicking. The Slate application is activated first, so this works with the game window in the background. force=true skips input synthesis entirely and invokes the widget's click delegate directly (buttons only), which bypasses hit testing and input blocking and can drive the game into a state a player cannot reach - it is synchronous, so unlike the default path the effect has already happened when the command returns. 'method' always reports which path ran (synth_input or delegate). Dimmed, disabled and non-hit-testable widgets are rejected outright. For a list entry, note the ref is only valid until the list scrolls - entry widgets are recycled, so scroll first (ui.scroll --to=index), re-query, then click. Passing x and y instead of ref clicks a raw viewport position; nothing verifies what it lands on, so prefer a ref. Fails when there is no world. | sin documentación oficial — el volcado es única fuente; requiere verificación en vivo | activo |
| **ui_close_coach_mark** | `ui.close_coach_mark(persist)` | Cierra todos los coach marks activos del mundo actual. **[EXPERIMENTAL]** | [EXPERIMENTAL] [CLI: ui.close_coach_mark] Ends every active coach mark overlay in the current world. With persist=true the coach mark keys are also recorded in the saved config so they will not be shown again on this machine. Fails when there is no world. | sin documentación oficial — el volcado es única fuente; requiere verificación en vivo | activo |
| **ui_close_cat_talk** | `ui.close_cat_talk()` | Cierra la superposicion cat-talk (Psycat) del tutorial inicial. **[EXPERIMENTAL]** | [EXPERIMENTAL] [CLI: ui.close_cat_talk] Closes the cat-talk (Psycat) overlay that gates the intro tutorial. Fails when there is no world, or when the overlay is not currently visible. | sin documentación oficial — el volcado es única fuente; requiere verificación en vivo | activo |
| **ui_click_popup_button** | `ui.click_popup_button(popup_id, list_key, Index)` | Hace clic en un boton de un popup abierto por la via normal. **[EXPERIMENTAL]** | [EXPERIMENTAL] [CLI: ui.click_popup_button] Clicks a button on an opened popup through the normal path (closes the popup, runs the bound script and delegate). 'index' is a BUTTON index within one popup - it is NOT the 'index' field of ui.get_blocking's popups[] array. The only popup selector is popup_id; without it the first enumerated open popup is used (enumeration order is UObject creation order, not z-order). Prefer list_key over index: the button order in Popup.json can change. A single positional argument binds to popup_id, so 'ui.click_popup_button NoticeBirth' selects that popup. A non-numeric index is rejected instead of being coerced to 0. Use ui.get_blocking to discover popup ids and button list_keys. | sin documentación oficial — el volcado es única fuente; requiere verificación en vivo | activo |
| **ui_dismiss** | `ui.dismiss(max_steps)` | Cierra la UI de bloqueo superior (hasta max_steps elementos por llamada). **[EXPERIMENTAL]** | [EXPERIMENTAL] [CLI: ui.dismiss] Closes the top-most blocking UI, up to max_steps elements in one call. Priority: coach mark -> cat talk -> popup -> ESC stack -> cutscene. For a popup it clicks the CANCEL button, never the action button: with two or more buttons it only clicks a non-dimmed Secondary/SecondaryNegative button and only when exactly one exists; a single-button popup is treated as an acknowledgement and is clicked. Clicking runs that button's bound script and delegate for real. Popup enumeration order is UObject creation order, NOT z-order, so the popup acted on is a best guess. Destructive confirmations (quit game, leave to lobby, delete, overwrite, discard, reset - matched as whole words, so 'Preset' is not read as 'Reset') are additionally on a deny-list and are NEVER auto-clicked; neither are popups with an empty popup_id, which are opened directly by a handler and cannot be verified as safe. A popup is closed outright (without clicking) only when its widget tree contains no button at all, so a popup that shows buttons never loses its decision delegates. When a popup is left untouched the call fails with stop_reason 'blocked_by:<popup_id> ...' (decide yourself and use ui.click_popup_button) or 'stuck:<popup_id> - all buttons dimmed' (nothing can be clicked at all). Loading screens are NEVER dismissed - poll ui.get_blocking and wait them out. Fails when there is no world. Safe to call repeatedly; within one call a target is never attempted twice. | sin documentación oficial — el volcado es única fuente; requiere verificación en vivo | activo |
| **ui_get_blocking** | `ui.get_blocking()` | Devuelve una instantanea de todo lo que bloquea la entrada de juego. **[EXPERIMENTAL]** | [EXPERIMENTAL] [CLI: ui.get_blocking] Returns a snapshot of everything currently blocking gameplay input: loading screens, modal popups, the cat-talk tutorial overlay, coach marks, cutscenes and the ESC (pop) stack. This is the polling command for automation: keep calling it until 'blocked' is false. When 'primary_kind' is 'loading' you must WAIT (it is not dismissable); for anything else call ui.dismiss. Popups and coach marks are reported only for the current world (empty when there is no world). This command never creates a widget, so it is safe to poll tightly. Popup body text is truncated to 200 characters to keep the response small. | sin documentación oficial — el volcado es única fuente; requiere verificación en vivo | consultivo |
